## 一、七条不可协商规则（R1–R7）

| # | 规则 | 违背后果 |
|---|---|---|
| R1 | `{{...}}` 原样，不译不改大小写 | 模板失效 |
| R2 | ` ```python ` / ` ```yaml ` / ` ```json ` / ` ```xml ` 原样 | 示例不可运行 |
| R3 | 含框线（`─│┌`）的无标记块原样 + 图注 | 915 块图错位 |
| R4 | 标题层级数量与原文一致 | 无法判断是否漏译 |
| R5 | 中文与拉丁字母/数字间加空格 | 排版不统一 |
| R6 | 首次出现用「中文（English）」 | 术语无法追溯 |
| R7 | 内部链接改为 zh 内可达路径 | 在 36 处既有失效外再新增 |

**R1 细则**：占位符列表见 `zh/PLAN/PLAN.md` §6「占位符保全」。G4 比对多重集，
数量与拼写任一不符即 FAIL。占位符可以移动位置（随句子语序调整），但不可增删改。

**R2 细则**：语言标记本身也是原文的一部分——` ```python ` 不得改成 ` ```py `。
G3 比对语言序列时逐项相同才算通过。

**R3 细则**：ASCII 图三档（A/B/C）见 PLAN.md §6。A 档为默认：原图一字不动，
图下加中文图注，格式见下文第 5 条。B/C 档改写时，原图必须完整放入 `<details>` 块。
G2 检查图体内出现全角字符即 FAIL——因为图注在块外，块内不该有中文。

**R4 细则**：`#`/`##`/`###` 的数量与原文一致。允许在文末新增「小结」和「延伸阅读」
各一个 H2（见 G9），除此之外不加不删。删标题一律视为漏译。

**R6 细则**：每个文件内首次出现时写「中文（English）」，之后只用中文。
`GLOSSARY.yaml` 的 `first_use` 字段给出了标准写法，优先照抄。
首次出现的判定范围是**单个文件**，不是全仓库。

**R7 细则**：指向仓库英文源文件的相对链接，改成指向 `zh/` 内的镜像路径。
已知 36 处上游本身就失效，清单与处理方式见 `zh/KNOWN_ISSUES.md`。

## 二、排版细则（12 条）

1. **中西文空格**：中文与拉丁字母、数字之间加一个半角空格。
   例：`128K 上下文窗口`、`使用 RAG 检索`、`第 3 章`。
   例外：全角标点前后不加空格（`，128K` 而非 `， 128K`）；
   行首行尾不加空格；代码块内不适用本条。

2. **标点**：正文用全角 `，。；：？！（）`；代码、路径、命令、URL 内用半角。
   不在中文句子里混用半角逗号句号。省略号用 `……`（两个），不用 `...`。

3. **代码块与 ASCII 图前后各留一个空行**（围栏行与相邻正文之间）。
   紧贴标题时，标题与围栏之间也留一个空行。

4. **图注格式**固定为一行引用块：

   ```
   > 图：<中文说明> —— <原文关键词>
   ```

   例：`> 图：原子提示的组成 —— 任务 + 约束 + 输出格式（TASK + CONSTRAINTS + OUTPUT FORMAT)`
   图注放在图块**下方**，与图块之间不留空行。

5. **标题**：只译文字，`#` 的数量与原文一致。标题内不加大括号、不加编号、
   不补全角句号。标题内的代码标识符与专名保留原文（如 `## 3. The `/recursive.memory.attractor.shell` Protocol`
   译作 `## 3. `/recursive.memory.attractor.shell` 协议`）。

6. **链接**：链接文字译，URL 不动。`[context window](https://...)` →
   `[上下文窗口](https://...)`。图片同理，`alt` 文字译、路径不动。

7. **表格**：表头译，分隔行（`|---|---|`）不动，列数不变。单元格内的代码保留原文。
   单元格内容过长时宁可换行也不合并列。

8. **引号**：中文用「」，嵌套用『』。原文用 `" "` 或 `' '` 时改「」，不保留英文引号。
   代码、文件名、变量名内的引号不动。

9. **数字与单位**：保留原文形态——`128K`、`3.5%`、`1,024`、`0.7`、`10×`。
   不改成「十二万八千」「百分之三点五」。计量单位（KB/MB/token/ms）不译。

10. **列表符号与缩进**保持原样：`-` 仍是 `-`，`1.` 仍是 `1.`，缩进空格数不变。
    不把 `-` 改成 `・`，不重排编号。

11. **不译**：变量名、函数名、文件名、目录名、CLI flag（`--only`）、JSON/YAML key、
    URL、包名、协议名（`RAG`、`MCP`）、`.agent.md` 一类文件名。
    这些出现在正文里也保持原样，哪怕看起来像普通单词。

12. **一行一句**：不要把原文的一段长句拆成多行（Markdown 软换行）。
    保持原文的段落切分，段落数尽量一致，便于逐段对照校对。

## 三、文件级要求

### front matter

每个译文文件开头必须有 front matter，字段见 `zh/PLAN/PLAN.md` §5「文件契约」。
`source_sha256` 与 `chunks` 由脚本写入，不要手改。G6 检查字段齐全且 sha 与源文件一致。

### 双语锚点

每个文件在 front matter 之后、正文之前放两行锚点（G8 检查）。

**不要手写这两行** —— `assemble.py` 按文件所在深度自动生成。相对层级写错是最常见的
复制粘贴错误（模板写死 `../../` 时，只有深度为 2 的目录才正确，全仓 185/242 篇会错）。
手写示例（`zh/00_foundations/01_atoms_prompting.md`）：

```markdown
> 原文：[00_foundations/01_atoms_prompting.md](../../00_foundations/01_atoms_prompting.md)
> 术语对照：[GLOSSARY.md](../GLOSSARY.md) ｜ 阅读路径：[LEARNING_PATH.md](../LEARNING_PATH.md)
```

| 译文位于 | 指向 `zh/GLOSSARY.md` 的链接 | 指向源文件的链接前缀 |
|---|---|---|
| `zh/*.md` | `GLOSSARY.md` | `../` |
| `zh/A/*.md` | `../GLOSSARY.md` | `../../` |
| `zh/A/B/*.md` | `../../GLOSSARY.md` | `../../../` |
| `zh/A/B/C/*.md` | `../../../GLOSSARY.md` | `../../../../` |

G8 会实际解析两条链接并检查目标存在且指向正确，光有「GLOSSARY」字样不算通过。

### 段级锚点

长文件每段开头插入（`assemble.py` 自动生成，不要手写）：

```markdown
<a id="chunk-2"></a>
<!-- chunk 2/3 | source_lines 120-310 | sha 4b1c... -->
```

## 四、自检

```bash
python zh/tools/check.py zh/00_foundations/01_atoms_prompting.md
```

九项全绿才可把 `status` 从 `draft` 改为 `published`。
G7 是警告不是失败：代码块外英文行占比 > 30% 时提示「中英夹杂」，
此时文件只能停在 `draft`，不能标 `published`。
